已按用户要求恢复暂停的 10,361 条原库存队列，并启动有限队列任务。当前阶段补采 GitHub Issue 详情、仓库状态、符合特征门槛记录的完整时间线与引用 PR 状态，然后通过生产存储入口重算任务特征、技能和推荐准入。

运行目录：`data/candidate_backfill_20261025_v1/`。

- `report.md`、`report_snapshot.json`：当前进度及两库可推荐数量。每个请求批次结束后更新，也可手动生成。
- `runner_state.json`：运行阶段、进程 ID、剩余额度；等待额度时记录恢复时间。
- `jobs.json`：全量身份和每条断点，保留待复核和待重试原因。
- `network_progress.json`：最近网络批次的实际请求数和额度。
- `evidence/`：每个成功或失败读取的来源记录；成功 payload 校验 SHA256。
- `source_error_archive/`：额外重试前保留的失败来源记录。
- `runner.stdout.log`、`runner.stderr.log`：本次有限队列任务日志。
- `*.sqlite3.before`：本轮开始前的两份 SQLite 一致性备份。
- `protected_tables_check.json`：已确认两份库各 32 张非候选业务表与本轮备份保持一致。

2026-10-25 恢复后的一个进度快照中，1,684 条已完成当前阶段处理，8 条待重试；两库当前可推荐数分别为网页库 589、默认库 588。该数字为历史快照，最新数量应读取运行目录内报告；仍有待处理队列，不能宣布全量补采结束。

## 运行方式

```powershell
python -u scripts/candidate_backfill.py collect `
  --directory data/candidate_backfill_20261025_v1 `
  --limit 10361 --request-budget 4500 --workers 4 --allow-network --until-done
```

恢复前先确认同一目录没有其他采集进程。任务使用已有 gh 登录或运行时环境变量，凭据不写入数据和日志。Windows 沙箱无法读取凭据管理器时，需要正常本机权限运行。

最多四路并发处理互不依赖的 GET；两份业务库串行写入。每个网络批次保留额度，每次最多申请 4,500 次请求，实际批次预算按当前剩余额度扣除预留量计算。额度不足时等待 GitHub 给出的重置时间，等待期间不发送补采请求。读取失败最多额外重试两轮；身份冲突、无法获取或持续异常保留为未确认。连续认证/限流阻断会退避并在三批持续阻断后停止，等待处理。

这是一项处理既有队列的有限本机任务；队列处理结束后生成报告并停止。需要暂停时终止匹配本轮命令的进程即可，已保存的来源和断点可复用。

## 口径

`verified` 表示完成生产状态检查，可能因关闭、占用、锁定等排除；`needs_task_review` 表示已获取详情但任务范围/类型/技能门槛不足，未宣称完成占用检查；`needs_retry` 表示读取或身份等异常。这些记录不会计为推荐通过。

当前阶段是规则推荐的数据核验与特征准备。完整代码历史、事前 Issue—文件定位、贡献/行为图、CodeBERT 向量和 CODER 训练权重仍需要独立补齐，不能把本轮 Issue 状态读取当作模型推理完成。

新增采集器测试 10 项通过，覆盖跨域拒绝、缓存时效/篡改、完整分页、凭据不落盘、并发请求预算、失败来源保护和整队列有限重试。既有库存接入集成测试 21 项通过。
