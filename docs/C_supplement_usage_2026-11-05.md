## 4. 读取文件和联接规则

主要数据目录：`data/midterm/working/sparse_expansion_20261104_handoff_v6/`。

| 文件 | C 的使用方式 |
|---|---|
| `outcome_index.jsonl` | 读取身份、目标 Issue、PR、时间、正文快照和来源 |
| `comparison_index.jsonl` | 384 条可联接样本及未标记同仓库候选键 |
| `source_manifest.json` | 解析来源包及指纹 |
| `account_coverage.jsonl` | 审核低历史用户的结果和画像时点覆盖 |
| `remaining_gaps.jsonl` | 人员数量缺口，不能当负标签 |
| `evidence_gaps.jsonl`、`candidate_rejections.jsonl` | 输入缺失和候选排除原因 |

画像目录：`data/midterm/working/sparse_review_profiles_20261105_v1/`。可先用 `joined_samples.jsonl` 做离线联接冒烟检查；正式实验应换成 B 审核后的历史冻结画像。

联接顺序：

1. 用 `outcome_id` 找结果。账号使用 `github_numeric_id`，不用 login 当稳定主键。
2. 用 `(github_numeric_id, profile_as_of)` 找画像；画像和联接表中的时间字段叫 `as_of`。
3. 用 `profile_key / profile_version / profile_hash` 固定输入版本，不能按用户取当前最终画像。
4. 正例内容在 `issue_content`，含历史正文、标题、时间和 `content_sha256`。
5. 用 `history_source_root` 找 `historical_controls.jsonl`，再以 `(issue_key, as_of)` 找对照快照；按其证据引用读取原始响应。
6. 原始结果证据相对 `evidence_source_root` 解析；没有该字段时用 `source_root`。不要把 PR 仓库当成目标 Issue 仓库：跨仓库关闭时使用 `repository`，另保留 `pr_repository`。
7. 代码可能来自多个包，按 `reused_contribution_keys` 或合并表 `sources` 解引用，并核对 commit、文件路径和内容哈希。

## 5. 首先做准入，不能直接拼接训练

当前分支另有 `datasets/temporal_xy_2024_2026_v3/`。本次补充的判重和缺口统计参照采集侧 v6，不能假设它与 C 当前实际使用的 v3 或其他数据版本完全相同。

请先记录实际基线的数据 manifest、画像版本、基础 checkpoint、编码器/仓库/用户映射及候选采样版本。将补充记录与该基线按 outcome ID、用户/Issue 关系和时间点比较，分别列出真正新增、恢复、重叠及排除项。

本包包含季度与 PR 创建前一秒两种时点，也包含 2024 年以前的数据。需要明确哪些范围准入，以及是否形成独立扩展实验。不要只修改时间字段或复用旧画像来匹配新样本。391 条也不等于可直接新增到实际训练集的 391 条样本。

ZIP 是本批使用证据的子集，不是旧原始缓存全量副本。它保证的是本批样本及画像所用证据；旧基线其他样本的源码、向量和模型资产仍需 C 已有资源，不能用本包补造缺失向量。

## 6. 必须完成的审计

### 时间和信息泄漏

代码事件必须早于画像截止点；标签发生在其后。原训练边界早于 2026-01-01 UTC，验证标签早于 2026-07-01 UTC，测试从 2026-07-01 起。若修改协议必须另立版本，不能用后期结果填训练历史。

真实曝光或推荐行为并未记录；PR 创建前时点只是研究采样策略，不代表该时刻真的向用户展示过候选。部分 commit 首次公开可见时间仍未独立证明，尤其需审核 PR 中后来添加但作者时间较早的 commit。对无法证明的记录排除或单独报告敏感性实验。

老师库转换时间的抽查结果与 GitHub 相差 8 小时；不要直接用未核实时区语义的数据推导画像截止点。语言元数据即使带版本时间，也不能未经审计回填历史事实字段。

### 标签和正例去重

把同一用户/截止点的所有已知正例作为多正例集合。相关性和排序指标按 Issue key 去重；原始 outcome ID 保留供追溯。重新与 C 的完整基线联接后，再过滤已知正例对照，避免遗漏旧数据中新确认的正例。

历史对照是 unlabeled，不是明确拒绝或不喜欢。不能把未完成、未点击或未记录行为当作用户负反馈。

### 基础模型已见范围

以前报告的 191 条新仓库测试结果仅按采集侧训练 X/Y 定义。必须另核对基础 checkpoint 的仓库映射和时间来源，才可做“未见仓库”结论。本次 392 条补充记录本身不是一个新的 191 条测试包。

## 7. 同仓库困难对照如何落地

本包已增加普通同仓库对照，但没有执行基础 CODER 分数筛选，不能称为困难负样本集已完成。

在准入的同一历史时点、可用状态与内容快照上，用固定基础模型给正例和候选打分，剔除已知正例，筛选与正例分数接近的对照。尽量达到每个正例 3～5 个有效对照，但实际不足时应保留数量和原因，不复制候选凑数。

保存 Issue key、正文 hash、候选集合 hash、原始基础分数、采样规则版本和随机种子。比较不同 Adapter 时固定同一候选集合。可靠语言/难度字段不足时，报告缺失覆盖；不得用未知字段构造“同语言、同难度”已满足的结论。

## 8. 建议的实验顺序与汇报内容

1. 验收包、完成基线判重和时间/映射审计，输出实际准入清单。
2. 接收 B 审核后的精确时点画像，核对维度顺序、mask、schema 和哈希。
3. 固定编码、候选池和基础模型，先运行联接/编码冒烟验证；记录缺失代码和编码失败，不填伪向量。
4. 建立新的数据版本，与旧冻结实验分开保留。比较基础 CODER、原 Adapter 和新增数据后的版本；测试集、候选与指标协议保持可比。
5. 报告整体、原低历史组、仍稀疏/未知画像组、同仓库困难对照和实际未见仓库组的样本量与 MRR、Recall@K 等既有指标。小样本组明确不确定性。
6. 对规则画像升级与数据增量分别作对比，避免把两者同时改变后的差异都归因于补采。

画像目前平均只观测 4.07/23 维，275 份画像仅有 8 种不同模型输入。该限制需要在实验报告中保留，不能因数据文件变大就假设个性化能力改善。
