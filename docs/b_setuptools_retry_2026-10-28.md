# setuptools 单仓库补采

目标是解决 `pypa/setuptools` 在 62 仓库补采中的唯一剩余失败，不改变已完成的 308 个仓库，也不覆盖此前失败记录。

本地输出目录：`data/b_setuptools_20261028_v1/`。jobs.json 保留原失败原因，report.md 给出本轮进度；新增快照在 s/ 下。

问题来自扫描到的部分历史提交：某些提交呈现独立 distutils 目录结构，没有在有界搜索中找到许可文本。其他选中提交的根目录存在 LICENSE。原采集器在第一个缺许可文件的提交处中止整个仓库，丢失了本来可以验证的其他提交。

修复后仍在原截止时间 `2026-10-26T00:00:00Z` 前最近 100 次提交内选样，最多取 10 次具有源代码和许可证据的提交、每提交最多 2 个源文件。未找到许可文本的提交保留 SHA、原始 commit 来源位置和路径证明，并标记 `license_file_not_found_in_bounded_search`，随后继续扫描。不会把仓库当前 LICENSE 冒充为缺许可提交的历史许可证据。

这是一种按证据可用性筛选的样本，不能表示完整历史、全部贡献者或全部许可条件。每个跳过原因都可在快照 manifest.source_provenance.selection.excluded_commits 中查看。来源校验器验证被排除 commit 的身份和树证明，也验证纳入贡献的作者、代码与固定 commit 的关系。

GitHub history 的 19 项离线测试通过，新增回归覆盖“遇到缺许可的历史树后仍取得其他有效贡献”，并验证篡改排除记录会被拒绝。

本次不提交、不推送 GitHub，不生成压缩包；数据保存在本地，最终状态以 progress.json、runner_state.json 和 verification.json 为准。

最终三批合计覆盖 309/309 个仓库，3,865 条贡献和代码版本记录，其中 3,715 个代码版本可用、150 个保留缺失原因；贡献作者账号关联已确认 3,847 条、未确认 18 条。开发者实体数量 1,538 是按仓库相加，不是去重人数。全量仓库覆盖只表示每库有界样本覆盖。
