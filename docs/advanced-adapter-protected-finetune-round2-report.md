# Advanced Adapter v1：保护式补采微调第二轮优化

日期：2026-11-05
状态：validation 探索完成；Top-5 门禁未通过；test 保持封存；不替换 RC1

## 结论

第二轮确认补采数据存在稳定的正向信号，但当前训练目标仍有明显权衡：小剂量补采可以提高整体 MRR、综合选择分和未见开发者 MRR，却会降低 Recall@5。由于用户看到的推荐首页质量不能只由整体 MRR 代表，本轮新增 `Recall@5` 守门并最终拒绝升级。

最重要的结果是：补采比例 2%、学习率 `5e-5`、margin 蒸馏 0.1 时，5/5 seeds 的 validation MRR 都超过 RC1；但平均 Recall@5 从 0.326146 降到 0.305121。因此不打开 test，不发布新 bundle。

## 新增发布门禁

训练器新增 `--max-recall-at-5-drop`。本轮冻结为 0.005：只有 validation MRR 超过当前最佳值，并且 Recall@5 不低于 RC1 Recall@5 - 0.005，checkpoint 才有资格替换 epoch 0。epoch 0 始终保留为安全回退。

检查 5 个 seed 的所有训练 epoch 后，没有任何 epoch 同时满足：

1. MRR > 0.250194845；
2. Recall@5 >= 0.321145553。

最接近的是 seed 20261104 epoch 1：MRR 0.250874671，但 Recall@5 只有 0.315363881，仍未通过门禁。

## 探索性后续对照

以下实验是在第一阶段结果之后提出的探索性假设，不与预先冻结网格混为一谈。

### 更小补采剂量

0.5% 和 1% 补采比例、`2e-5`/`5e-5` 学习率仍能产生最高约 0.251101 的原始 MRR，但 Recall@5 只有约 0.3046–0.3073，全部被新门禁回退。说明 Top-5 下降并非单纯由补采比例过大造成。

### 更强 margin 蒸馏

将 margin 蒸馏从 0.1 提高到 0.5、1.0、2.0，最高 Recall@5 可恢复到 0.318059，但对应 MRR 不再超过 RC1。更强蒸馏能保护旧排序，却同时抑制新数据带来的增益。

### 困难负例权重

将困难负例权重从 1.0 调高到 3、5、10 会同时降低 MRR 和 Recall@5；调低到 0、0.25、0.5 时，最高原始 MRR 为 0.251684，但 Recall@5 仍只有 0.307278。困难负例重加权不能解决当前权衡。

## 解释与下一步

现有训练目标主要优化 20 个正负 pair 的平均 BPR 损失。它可以让更多正确 Issue 进入 Top-10、改善冷启动用户，却不直接优化“正确 Issue 必须留在 Top-5”。下一步不应继续扩大参数搜索，而应修改目标函数：按 outcome 组织完整候选组，引入 listwise softmax / ListMLE 或可微 NDCG 类损失，并保留 RC1 蒸馏与 Recall@5 门禁。新目标需要先在 validation 上证明能同时保持 Top-5 和 MRR，再进入多 seed；test 继续只允许最终候选打开一次。
